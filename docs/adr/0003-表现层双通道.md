# ADR-0003：表现层双通道 —— 宏观终端 与 叙事终端/网页

* 状态：**已采纳**
* 日期：2026-10-31
* 适用：`run.py` 的报告 / `--live` / `--serve`、`apps/terminal*.py`、`apps/archive.py`、`apps/render.py`、`apps/viz.py`，以及后续的 `apps/dialogue.py` / `apps/logs.py` / `apps/scenes.py`
* 关联：[ADR-0002](0002-原著还原层与零专名边界.md)

---

## 1. 背景

此前的口径是「不模拟地图、对话、战斗、城邦」（`docs/使用教程.md`）。这句话在**引擎层**是对的：
`kernel/` 不该长出对话系统。但它被误读成「整个产品都不呈现对话」，于是：
叙事内容被压进报告里几行 `emit` 镜头，角色、地点、对白没有自己的载体。

需求侧要的其实是**分工**，不是二选一：

* 打开项目，先要知道**世界整体走到哪了**（阶段、进程、裁决、换代、读数）；
* 想细看时，再去**另一个界面**读角色、城邦、地点、对白、独白与终端文本。

---

## 2. 决策：两条通道，各自只做一件事

| 通道 | 载体 | 内容 | 允许写状态 |
|---|---|---|---|
| **宏观通道** | `run.py` 报告、`--live`、`--serve` 看板 | 阶段推进、演算进程、裁决与终局、十二席状态、指标曲线、编年史**事件**（不含台词） | 否 |
| **叙事通道** | 独立终端窗口（`--terminal-window`）+ 网页叙事视图 | 角色、城邦、地点、对白、独白、日志、终端文本、档案 | 否 |

### 2.1 各自的输入

| 通道 | 输入 |
|---|---|
| 宏观 | `Trajectory` / `State`（既有读数），不读 `lore/canon/` |
| 叙事 | `lore/canon/`（已编译语料）+ 当前帧的**只读观测快照**（`session.observe()`） |

叙事通道是「**按当前世界状态，把已有文本放到它该出现的位置**」，不是让模型现场生成台词。
换言之：引擎仍然不模拟对话；对话是**回放与编排**，不是**生成**。

### 2.2 位置与开关

| 项 | 约定 |
|---|---|
| 默认档位 | **`suggest`**：读语料、产出建议内容，但不写状态 |
| 既有预设 | 没有 `canon_bundle` 配置 ⇒ 行为等价 `off`，报告逐字不变 |
| `drive` | 仅限 `presets/canon-drive`、`worlds/generated/`，需单独基线 |
| 网页叙事视图 | 与看板同源（`--serve`），但走独立路由/面板；删掉不影响演算 |

---

## 3. 与「不模拟对话」的关系

保留的约束：

* `kernel/` 与 `apps/` **不生成**对话文本，也不做语言模型调用；
* 台词只以 id 形式进入程序，文本从 `lore/canon/dialogues.jsonl` 取；
* 叙事通道只读，删除后演算逐帧不变。

放弃的读法：

* 「产品里不能出现对话」——不再成立。对话出现在叙事通道，且是回放性质。

`docs/使用教程.md` 的那句话将改为：「引擎不模拟对话；对白由只读叙事层按语料回放」。

---

## 4. 后果

**正面**

* 宏观报告不再被台词挤占，`plot` / `plot-full` 的输出口径不必反复权衡；
* 叙事内容有独立载体，体量可以增长而不影响读数；
* 两条通道可以分别验收：宏观看指纹与断言，叙事看逐字率与覆盖率。

**负面**

* 多一套界面与路由要维护；
* 「当前帧该显示哪一句」需要一套确定性的选择规则（按 `frame` / 场景 / 触发条件），
  规则本身要进 `lore/canon/scenes.jsonl`，不能散在代码里。
