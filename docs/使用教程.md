# 使用教程

δ-me13「翁法罗斯」演算引擎 —— 从跑到看懂，再到自己改。

> 想先要一份最短的说明，看 [README](../README.md)；本文是详细版。
> 概念与名词对照见 [术语对照表](术语对照表.md)；外部变量考据见 [外部变量.md](外部变量.md) 与 [外部变量.json](外部变量.json)。

---

## 一、这是什么

一句话：**它把「十二位 → 再创世 → 永劫回归」这件事，从文案变成了一段真的会跑的演算。**

它复刻的不是剧情过程，而是底层的**真相层**：一台被外部反复干预的抽象演算，十二个「位」上的人不断更替、熵不断累积、变量域走完、世界陷入停滞、最后由外生变量决定它得出什么结论。

**它是什么**

* 一台**逐帧演化**的动力学系统：每帧算漂移、相互作用、承位、竞争淘汰、补种、分化、能力凝结、熵、变量域推进、再创世。都是数值运算，没有一条规则是「到第 N 帧就写一句话」。
* 一个**结论机**：终止条件不是「跑够多少帧」，而是「命题能不能裁决」。判据表写在配置里（见 §9.3）。
* 一个**可复现的实验台**：同一组 `(seed, 预设, 外生输入)` 必定演算出同一个世界，逐帧一致 —— 这一条有专门的自检工具守着。

**它不是什么**

* 不是游戏，不是剧情播放器，也不模拟地图、对话、战斗、城邦。
* 引擎内核里**没有专有名词**：它只认 `locus / slot / agent / overflow / promotion`。名字、职位、神话全是**渲染层事后贴上去的** —— 换一套词表，同一段演算就被讲成另一个世界。
* 不联网、不需要前端框架、不需要数据库。只有 numpy 一个外部依赖。

**三条红线**（改代码时必须守）

| # | 红线 | 为什么 | 谁在守 |
|---|---|---|---|
| 1 | `engine/` 里不许出现专有名词 | 保证「引擎通用、神话外置」 | `tools/grep_forbidden.py`、`tests/test_forbidden_words.py` |
| 2 | 改轨道配置必须重测全部期望值 | 动 `loci/params/genesis` 会改变轨迹 | `tools/snapshot.py` 会先红给你看 |
| 3 | 可视化层只读，绝不回写状态 | 保证「删掉渲染，演算逐帧不变」 | `tests/test_viz.py` |

## 二、五分钟上手

### 1. 装依赖

```bash
python -m pip install -r requirements.txt     # 只有 numpy
```

要求 Python ≥ 3.10。装好可以先自检一下：

```bash
python tools/export.py --check-only           # 解释器 / 依赖 / 数据是否就绪
```

### 2. 跑一次（涌现版）

```bash
python run.py
```

这跑的是**涌现版**：不绑定任何名字，角色与轨迹全部自己长出来。它会很快停在结论上，然后打印一份报告 —— 报告的每一段怎么读，见 §5。

### 3. 跑一次剧情锚定版

```bash
python run.py --preset plot
```

这一版把名字按剧情钉在个体上（**只改渲染，不改轨迹**）。它会跑完三千三百多万帧的循环，最后给出「结论被改写」。想边跑边看编年史：

```bash
python run.py --preset plot --live             # 实时刷屏
python run.py --preset plot --log              # 只落盘：logs/翁法罗斯编年史_演算N.txt
python run.py --preset plot --log 编年史.txt    # 只落盘到你指定的文件
```

### 4. 导出一份可视化看板（或边演算边看）

```bash
python run.py --preset plot --export          # 跑完后导出单文件看板
python run.py --preset plot --serve           # 起实时看板，浏览器里边演算边长（演完可回放）
```

`--export` 会生成 `dashboard/翁法罗斯-可视化.html` —— **单文件、零外部依赖、不联网**，双击用浏览器打开即可
（想放到别处就 `--export 我的路径.html`，目录会自动创建）。
`--serve` 则起一台本地只读服务并自动打开浏览器，页面随演算实时更新。看板能做什么见 §6。

### 5. 跑一遍全部自检

```bash
python tools/selfcheck.py                      # 快档，几十秒
python tools/selfcheck.py --full               # 四个世界的全量验收 + 判据 4/5（数分钟）
```

## 三、命令行参数全解

```
python run.py [--preset 名] [--seed n] [--frames n]
              [--live] [--log 路径] [--export [路径]] [--serve [端口]] [--no-open]
              [--serve-reload | --no-serve-reload]
              [--verbosity 档位] [--json] [--dump-anchors]
              [--explore [K]] [--fast [K]] [--list-presets] [--help]
```

| 参数 | 作用 | 备注 |
|---|---|---|
| `--preset 名` | 选世界：`emergent`（默认）/ `plot` / `plot-mech` / `nullify` / `destruction` / `tide` / `refuted` | `--list-presets` 可列出 |
| `--seed n` | 换世界种子 | **只影响角色涌现与命名，不改变裁决结果与时刻** |
| `--frames n` | 只跑到第 n 帧 | 调试用；跑不满会看到断言失败，属正常 |
| `--live` | 实时输出编年史 | 只读，删掉它演算不变 |
| `--log [路径]` | 编年史落盘 | 不配 `--live` 时只落盘不刷屏；不给路径就写 `logs/翁法罗斯编年史_演算N.txt`（N 递增，不覆盖旧的）；落盘后会在终端提示文件路径 |
| `--export [路径]` | 导出单文件 HTML 看板 | 不给路径就写 `dashboard/翁法罗斯-可视化.html` |
| `--serve [端口]` | 起只读实时看板服务并自动开浏览器 | 默认端口 8765；演完转回放台，`Ctrl+C` 结束 |
| `--serve-reload` / `--no-serve-reload` | 配 `--serve`：演完后**是否自动重载**成完整静态页 | 默认**开**；用 `--no-serve-reload` 关掉，改为右下角弹「演算完成」提示，点「立即查看」再切过去 |
| `--no-open` | 配 `--serve`：不自动开浏览器 | 自己访问打印出的地址 |
| `--verbosity 档位` | 逐类别控制编年史字数 | 见下 |
| `--json` | 额外打印机器可读结果 | 便于脚本消费 |
| `--dump-anchors` | 导出命名标定语料到 `data/anchors.jsonl` | 换种子后重新采集角色用 |
| `--explore [K]` | 探路档：时间刻度按 K 压缩 | **只验机制连通，不能当验收** |
| `--fast [K]` | `--explore` 的旧名，等价 | 同 `--explore` |
| `--list-presets` | 列出可用预设 | |

### `--verbosity` 怎么用

档位 `0` 静默 / `1` 摘要 / `2` 常规 / `3` 详细。可以给一个数字，也可以按类别覆盖：

```bash
python run.py --preset plot --verbosity 1                      # 只看大事件
python run.py --preset plot --verbosity 2,deadlock=3            # 常规，但死循环那一类要详细
python run.py --preset plot --verbosity emergence=0,deadlock=2  # 关掉涌现刷屏
```

可选类别：`converged`、`deadlock`、`disturbance`、`domain`、`emergence`、`promotion`、`prune`、`solver`、`succession`、`verdict`、`violation`。它**只影响渲染** —— 删掉这一整块，演算逐帧不变。

### 几个典型组合

```bash
# 换个世界看看：同一个引擎，另一种角色与另一种结局
python run.py --seed 7 --preset plot
python run.py --preset nullify                  # 「未被拯救」的分支：走不出去，终局「证伪」、不升格
python run.py --preset plot-mech                # 把剧情写成机制：断言与时间线全过，但世界走向不同
python run.py --preset destruction              # 「毁灭」结论的演示世界（最小的退化预设）
python run.py --preset tide                     # 「被潮水吞没」的世界：为自身耗尽

# 调试：只看前 3000 帧，静默大部分输出
python run.py --preset plot --frames 3000 --verbosity 1

# 机制连通性快速验证（几秒）
python run.py --preset plot --explore 100
```

## 四、七个世界

每个预设只提供**演算之外**的东西：固定种子、名字绑定、额外外生事件、期望清单。**它不含任何一条演算规则** —— 换掉预设，同一个世界的规则一字不改。
（唯一例外：`refuted` 自带一份 `genesis.json`。因为 `all_falsified` 是**世界无关**的量 —— 探针只读初始变量域 / 阶段装配 / 参数，不读世界状态 —— 所以「证伪」只能由一个**初始变量域不同**的世界来演示，见下表。）

| 世界 | 它是什么 | 关键读数（seed 0 实测） |
|---|---|---|
| `emergent` | **涌现版**：不出锚定、不加扰动、不带期望。名字与轨迹全由演算自己长出来 | 裁决 `proved` @2,000 —— 十二位在**两路探针下**全被证伪即判（`all_falsified` 不要求变量域穷尽，故早于域穷尽@10,999） |
| `plot` | **剧情锚定版**：末世的十二位与人名按剧情钉住；外生剧本复刻「外部干预 → 永劫回归 → 记忆覆写」 | 断言 **15/15**、时间线 **29/29**；裁决 `overwritten` @33,594,547；迭代 52,411（复用 33,550,334 帧）；轮回 **33,550,336** 次 |
| `plot-mech` | **机制版**：与 `plot` 同源，但把六处剧情从「只登记」升级为**真机制**（逐出 / 交涉），并照旧把剧情事件登记进账本 | 断言 **15/15**、时间线 **29/29**（与 `plot` 同一套判据全过）；换代 **48**（`plot` 是 82）—— **剧情口径一致，世界走向不同** |
| `nullify` | **否定版**：原著的「未被拯救」分支 —— 删掉终局那次覆写与写入记忆。世界一路停在毁灭方向 | 断言 **12/12**、时间线 **21/21**；裁决 `destruction` @33,594,547（迭代 52,407）；**升格** |
| `destruction` | **毁灭版**：为「毁灭」这条结论准备的可达世界 —— 最小的退化预设，无剧情、无名字、无施为者 | 断言 **3/3**；裁决 `destruction` @2,000（**升格**） |
| `tide` | **淹没版**：为「耗尽」这条结论准备的可达世界。外生剧本持续抬高溢出量，越线后淘汰门槛从「年老」改为「被同化得最深」 | 断言 **6/6**、时间线 **8/8**；裁决 `annihilation` @20,000；吞没 **6,211** 次 |
| `refuted` | **证伪版**：**自带 genesis** 的世界 —— 三档都不装机制门、都是短寿命、`disorder` 全 0 ⇒ 探针永不达标（`all_falsified` 永不成立）；外生剧本让岁月之位永久缺位 ⇒ 结构冻结 | 断言 **5/5**、时间线 **5/5**；裁决 `refuted`；**不升格** |

`plot` 与 `nullify` 的区别只有**两处外生输入**（覆写方向、写入记忆），世界规则完全一样 —— 这正是「是 `converged` 的有无决定了世界的两条路」的证据。

**判据表四个维度各有其演示世界**：`proved`←`emergent` · `refuted`←`refuted` · `destruction`←`destruction` / `nullify` · `annihilation`←`tide`。另有**不属于判据维度**、由外生改写产生的结论 `overwritten`←`plot`（同源的 `plot-mech` 亦然）。

## 五、报告逐段导读

跑完一次会打印五段。以 `plot` 为例：

### 头部：这次实验的身份证

```
  命题        求：生命的第一因   [P_LIFE_FIRST_CAUSE]
  位表        12 位 × 12 维
  世界种子    0    预设 plot
  帧预算      33,594,607
  实际迭代    52,411   （沿参考轨道复用 33,550,334 帧 —— 结构未变，不算第二遍）
```

**「实际迭代」远小于「帧预算」是正常的**：世界结构长期不动时，后续帧沿参考轨道复用，不再逐帧重算。这不是偷工，`tools/reuse_equivalence.py` 会核对「复用期算出的每一帧签名 == 逐帧真跑同一帧的签名」。

头部后面还会逐行给出：**音位风格**（命名器的两个偏好，只影响命名、不改轨迹）、**走到帧**（真终局那一帧及其历法换算）、**最终状态**（轮回计数 · 世代更迭次数 · 末态熵 · 黑潮强度）与**世界纹理**：

```
  世界纹理    相似度中位 0.080 · 能量集中度 0.086 · 区域连通分量 4   （只读观测，不进指纹）
```

**「世界纹理」**把末态压成三个低维统计，一眼看出世界「抱团 / 集中 / 分块」到什么程度：**相似度中位**越高越抱团、**能量集中度**（承载量的赫芬达尔指数）越大越压在一席、**区域连通分量**是已承位席按向量相似度连边后的块数。它是**纯观测**：不进摘要指纹、不参与演化 —— 删掉这一行，演算逐帧不变。

> 走到帧若落入冻结区，下面还会多一行**死循环**读数（轮次 / 尝试 / 留痕）—— 结构长期不推进时后续帧沿参考轨道复用，不再逐帧重算。配了 `domain.stages` 的世界另有「阶段目录」与「世界规则」两块。

### 头部下面那块「阶段目录」与「世界规则」（配了 `domain.stages` 的世界才有）

四档初始变量域各跑了多久、**本档新装**了什么机制、期间发生了什么、以及 wiki 口径的该档结论：

```
  阶段目录    （每一档跑多少帧 · 新装了什么机制 · 期间发生了什么 · 该档的结论）
    ① 无机演算期  帧 0–1,998（预算 2,000） 新装 —　覆盖 life_span=175
       └ 完全有序的思维模式；习得固定阶段后仍产生无序
       读数：涌现 202 个 · 自动更替 10 次 · 消亡 502 个
    ③ 人类演算期  帧 5,999–10,998（预算 5,000） 新装 记忆继承机制、分化机制、嵌合协议、主动更替　覆盖 mutation=0.01　（更替由此从【自动】改为【主动】）
       读数：涌现 149 个 · 主动更替 9 次 · 消亡 2,889 个
    ④ 再创世演算期  帧 10,999–33,594,547（预算 —）
       └ 再创世与世代更迭；最后一次被外生变量改写 ⇒ 永劫回归
       读数：涌现 1,015 位 · 再创世 44 次 · 陨落 22,358 人

  世界规则    （换代时把什么当成下一世的规则）决策账本（主动更替 @6,000） · 主导支 0 · 共识 8.3% · 共识门 ≥ 0.115（末态 0.133）
    order 80.2358 · entropy 13.2969 · fertility 56.7600 · strife 16.0397 · wealth 50.8556 · faith 72.9753
```

「新装」只列**本档新开**的机制门（后一档会自动保留前一档的），「覆盖」是该档对运行旋钮的改动。一次演算**从无机一路走到末阶段**，不是四个预设。注意 ①③ 与 ④ 的**量词不一样**（个 / 位 · 消亡 / 陨落）—— 那不是笔误，见下面那条。

### 两套语汇：演算期 ⇄ 世界内

**同一段演算，前三个阶段与第四阶段是两套词。** 据 wiki：十二因子以【无机生命 / 有机生命 / 人类】为初始变量跑了**三个阶段**，那时它们只是**电信号 / 十二种生命原动力的简化模型**（biligame「实验进程：无机 / 有机」·「十二因子」）；到**第四阶段**才把背景设为**人类古典文明**，「**其中十二因子便成为十二泰坦 / 黄金裔**」（moegirl 第 47 行）。所以：

| | 前三个阶段（`sim`） | 第四阶段（`myth`） |
|---|---|---|
| 那十二位 | **十二因子**；点名用「第 N 号原动力」/「因子 <词根>」 | 十二泰坦；点名用职位（负世 · 岁月…） |
| 个体 | **电信号**（涌现 / 归入第 N 号原动力） | 黄金裔 / 半神（涌现 / 接掌「X」之位） |
| 计数 | 原动力 · 消亡 N **个** | 火种 · 陨落 N **人** |
| 时间 | **第 N 次循环**（还没有历法） | 纪元 · 月 · **光历 N 年** |
| 城邦 / 称号 | **不显示** | 奥赫玛 / 全世之座… |

切换点不靠配置猜：取 Telemetry 里 `DOMAINS_EXHAUSTED`（变量域走完 = 人科人属那一档跑满）那一帧 —— 报告、编年史、看板、席卡共用同一把尺子。词表在 `config/lexicon.json` 的 `phase_terms.sim`（只列要改的叶子，其余照顶层）；看板的席卡会在回放跨过那条线时**就地换词**。演算期那 12 位怎么点名由 `sim_slot_naming` 定（`ordinal` / `stem` / `both`）。

**同一个机制换了三次名**（都跟着 wiki 走）：更早叫**自动更替**（十二位齐备即换代 —— 它自始就有）；**第三阶段**内、协议改写那一刻起叫**主动更替**（biligame 第 19,110,218 次循环「将自动更替循环修改为电信号主动更替」；moegirl 第 41 行「第三阶段…完成了主动更替循环的行为」）；**跨进第四阶段**才叫**再创世**（moegirl 第 47 行「第四阶段…利用「再创世」进行世代更迭」）。两处界都不靠配置猜：前者取 Telemetry 里 `renewal.mode` 进覆盖表的那一帧，后者取 `DOMAINS_EXHAUSTED` 那一帧 —— 编年史 / 时间线打点 / 阶段卡共用这一把尺子。

> 注意**第三阶段仍是演算期措辞**（因子 / 原动力 / 消亡 N 个 / 第 N 次循环），只是**机制名**先走了一步 —— 那批因子要到第四阶段才成为世界内的身份，所以它在这一档里叫「主动更替」而不是「再创世」。整个机制另有一个**不分档**的统称「世代更迭」，聚合读数（最终状态 / 曲线图例 / 背负累计）用它。

**「世界规则」那两行**是换代时写下的规则（`rule_matrix`）与它在 6 个观测量上的投影（名字取自 `config/mapping.json`）。规则本身**不参与演化**，也不进轨迹指纹 —— 所以「主动更替」把规则来源从席位向量换成决策账本，**不改一个比特的轨迹**。但**「共识门」是触发条件**：阶段三起换代还要「决策共识」（主导支池内占比）≥ `renewal_consensus`（`config/params.json`，默认 0.115）—— 这一条是**真机制**，改它轨迹就变；再创世的逻辑被外部协议覆写（`promotion.mode` → `memory_converge`）之后，换代归那套新逻辑管，这道门不再适用。同一份数据在看板上是**阶段卡 + 时间线顶端的阶段带 + 世界规则块**。

### 【一】演算历程

编年史。连续同型的事件会被折成一条并附计数徽标：

```
  帧   52,000  ⟳ 第 7,953 次轮回，卡厄斯兰那又挡下了一次升格 —— 已等待 10,000 帧
  帧   16,000  ◆ 白厄未能通过纷争试炼，万敌通过试炼晋升新的纷争半神 —— 盗火行者随黑潮而来
```

### 【二】涌现出来的角色

数据文件里没有任何一个角色，他们是演算长出来的。注意「承位」列是**职位**（负世/岁月…），不是人名 —— 名随人走，席位换手不换名。

「城邦」列是**可空缺**的渲染层绑定（`config/lexicon.json` 的 `cities`）：只填有考据的席位，没有的显示 `—`。
它与「称号 / 圣所」（`regions`）是两层 —— 前者是城邦，后者是泰坦的称号，别混。改它**不影响轨迹**（纯渲染）。

### 【三】断言核对（剧情在这里，但它是断言）

每一条都是「跑不出来就是引擎错了，而不是回来改数据」的判据。`PASS/FAIL` 一目了然。

### 【四】预设时间线核对

期望清单（哪些事在什么帧之前发生）。**引擎从不读它** —— 它只用于报告核对与种子检索。

### 【五】判定与结论

```
  裁决        结论被改写（overwritten）  结论已被外生变量改写，判定于第 33,594,547 帧
  载入核心变量后方程被外生覆写：生命的第一因是「你好，世界」   [C_CONCLUSION_OVERWRITTEN]
  结论链      2,000:归于毁灭 → 33,594,383:证真 → 33,594,527:结论被改写
```

**「结论链」是这里最值得看的一行**：世界中途改过主意几次、分别在什么时候 —— 上例读作「纳努克的目光把方向拨向毁灭，先判『归于毁灭』；走出永劫回归、外力改写演算方向的那一刻（33,594,383）两路探针改判『证真』；最后被外生变量改写成『结论被改写』」。

**「议题框架」是一句固定说明**（取自 `config/conclusions.json` 的顶层 `_framing`）：它把「裁决」定性为**测量**而不是形式证明 —— 程序不理解命题，它只查表拼接文案。这一行存在的意义是**防止误读**。

**「裁决依据」摊开十二席各自的读数**。从 R3 起判据是**两路探针**，报告只印第一路（第二路 `progress2` 只在内部读数，未随 `--json` 输出）：

```
  · 裁决依据  经验裁决：各席读数为「单独消融该席后迷你世界的熵 / 阈值 τ」，≥τ 即该席被证伪 —— 这是【测量】而非形式证明
              　　负世 1.18/1 · 岁月 1.21/1 · 门径 1.26/1 · 律法 1.25/1 · 天空 1.21/1 · 大地 1.20/1 · 海洋 1.17/1 · 理性 1.19/1 · 浪漫 1.24/1 · 诡计 1.26/1 · 纷争 1.24/1 · 死亡 1.19/1
              　　达标 12/12（100%） · 最勉强「海洋」1.17（裕度 1.17×τ）
```

`progress` 是连续量（= 消融熵 / 消融阈值）：达到 `τ`（`config/params.json` 的 `tau_falsify`）即该席被证伪。
**但从 R3 起，证伪要求两路都达标** —— `progress` 是「**独留**这一席」的口径，`progress2` 是「**拿掉**这一席、其余十一席是否照样失序」的口径
（分母取「十二席全在」的基准世界，两者因此同量纲，但**达标线不同**：路 A 用 `tau_falsify`，路 B 用 `tau_falsify_band`，默认 0.8）。只要还有席位没达标，结论就会落到「未决 / 证伪」那一边。
因为它是连续量（不是「是 / 否」），`tau_falsify`（路 A）与 `tau_falsify_band`（路 B）都是**真的可调阈值**：前者调大更容易落到「未决」，后者调大则更难证真（**改它们都会动轨迹，须重测**）。
这一行与 `--json` 里的 `progress` 同源，纯只读（删掉它，演算逐帧不变）。

**没有外生变量来收场的世界会多一行「· 升格」** —— 产物直接外溢：

```
  · 升格     未被改写的「归于毁灭」结论外溢（原著中的绝灭大君）
```

（`destruction` 与 `nullify` 都有这一行；`refuted` 是唯一**不升格**的演示世界。）

裁决短名与停因长句都取自配置（`config/conclusions.json` 的 `label` / `stop_label`），**报告层不写死任何一个枚举** —— 加一个新维度不用改代码（见 §9.3）。

## 六、可视化看板怎么用

### 6.1 导出静态看板

```bash
python run.py --preset plot --export
```

生成的 HTML 是**自包含**的（内联 CSS + 原生 JS，图表也由 JS 现场绘制，零外部依赖、不联网），直接双击打开，不需要起服务端。

四块内容：

1. **十二席状态** —— 每席显示职位、称号 / 圣所、**城邦**、在位者、状态（在位 / 空置 / 封印）与证伪进度条。
   顶部有「城邦」图例：**按城邦分组着色**（每个城邦一个颜色的圆点，席位卡上的圆点与图例同色）；
   没有考据的席位显示 `—`、不画点。城邦只是渲染层绑定，缺了它页面照常。
   > **城邦 / 称号只属于第四阶段**：世界还没走到「初始变量域穷尽」（如 `emergent`），
   > 席位卡不摆这两行、图例整块不出现，报告里的「城邦」列也一并省去 —— 那 12 位在
   > 演算期还没有世界内的身份。回放跨过那条线时，页面就地换词（见 §一「两套语汇」）；
   > 鼠标停在某张席位卡上，会跟出一个灰字小卡报这位的**电信号序列**编号：`词干 + 序号`——
   > 词干取**这个体所属的因子**（与席位名同一把尺子，所以第 2 号原动力上的人必是 `Leoreia…`），
   > 序号**按因子各自成一条序列**（同因子的第 1、2、3… 位依次领 1、2、3…，预设预分配掉的号跳过）。
   > 而**外部变量**（自天外而来、不是从池子里长出来的那几位）报 `外部变量 · ?` —— 他们本就没有工序号；
   > 由「记忆」承载的席位同理。
   > 这几位在 `plot` 里是【真正的场外参与者】：不进池、不算涌现，由预设的 `bind_participant`
   > 事件在指定帧**直接接掌**某一席（开拓者 @33,594,387 接负世、丹恒 @33,594,447 接大地），
   > 那一席自此**不被活体争夺**；`nullify`（否定版）不接这一手，那一席是被清空的。
2. **指标曲线** —— 熵 / 溢出强度、种群 / 在位席位，**对数帧轴**（否则长尾会把前期压成一根线）；
   世代更迭处以竖虚线标出（图例里那个聚合名是**世代更迭**；逐条打点才分「自动更替 / 主动更替 / 再创世」三档，见【一】的说明）。曲线右端永远是**演算真正走到的那一帧**，最后一次换代不会被采样窗口漏掉。
3. **事件时间线轴** —— 对数帧轴上打点，死循环区段以红底高亮。节点文字**默认不显示**：
   鼠标靠近某个节点，才展开它的引线与文字（淡入 / 引线伸出 / 文字裁剪展开的过渡）；
   勾选「常显全部节点文字」则按「放得下才显示」的规则常显。图上另有一条浅蓝虚线，
   标出**演算期 ⇄ 世界内**（十二因子成为泰坦 / 黄金裔）那条分界。
   也可以勾选「改为逐条列出全部事件（不打点）」改看纯列表。
4. **编年史** —— 连续同型事件已折叠；可按关键词过滤、点席位卡按人过滤、输入帧号定位到最近一条并自动滚动。

交互要点：

* **放大 / 缩小**：在任意一块图上滚轮缩放、按住拖动平移，或点「＋ / － / 重置」；
  曲线与时间线共用同一个时间窗，一起缩放 —— 挤成一堆的时间线标签只要拖近就能拉开。
* **回放台**：摘要卡下方是回放控制台 —— **回到开始 / 前一帧 / 播放暂停 / 后一帧 / 跳到末尾**，
  外加速度（×1–×64）与可拖动的进度滑块。可暂停、播放，或跳到任意时刻，看**当时**的十二席与编年史
  （编年史只显示「已发生」的行）。进度条按**对数时间轴**走，与图表横轴一致，拖动时游标平滑跟随。
* 在搜索框输入「接掌」→ 只看席位易主的那些行。
* 点某张席位卡 → 按这位在位者过滤（**再点一次、或点页面任意空白处即可取消**，取消时联动清空过滤词）。
* 在「跳到帧」里输入 `33594383` 再点「定位」→ 高亮最接近的那条，时间线轴上的游标也会跟着走；
  鼠标一划走，节点读数就收起（只有「定位」留下的那句会继续留着）。
* **双击时间线上的某个节点** → 编年史翻到那一帧那条，自动滚过去并高亮（等同于用「定位」定位到它）。
* 点「初始变量域 · 四个阶段」里的任意**阶段卡** → 回放直接跳到该档**开始的帧**（采样时就把换档帧钉住了，落点是精确的）。
* 鼠标在图上来回移动 → 浮出该帧的读数。

它只是**只读渲染层**：不加 `--export` / `--serve`，或者把 `engine/viz.py`、`engine/live.py` 整个删掉，演算逐帧不变。

### 6.2 实时看板（`--serve`）：边演算边看

静态导出看的是**跑完之后**的快照；`--serve` 看的是**正在跑的世界**：

```bash
python run.py --preset plot --serve                  # 起服务并自动打开浏览器（默认 :8765）
python run.py --preset plot --serve 9000 --no-open    # 指定端口、不自动开浏览器
```

它会用**标准库**起一台本地、**只读**的 HTTP 服务：页面每 0.7 秒向 `state` 取一次**增量**，
于是十二席、曲线、时间线、编年史、**阶段目录**随着演算一起长出来，页面上会显示当前帧号。
演算结束时，页面自动切换成**回放台**（顶部摘要卡替换成终局结论），可暂停 / 播放 / 跳到任意时刻回看整体走势。

> **演完后会自动换成完整静态页**：服务端在演算结束的那一刻，用与 `--export` **完全相同**的
> 一次渲染备好完整页面；页面随后自动重载，此后你看到的就是与导出单文件**内容一致**的那一张
> （阶段目录、世界规则、城邦图例等静态块一并补齐）。所以**只开 `--serve` 也不会缺内容**，
> 不需要另外跑一次 `--export`。

* 服务只在 `127.0.0.1` 上监听，不对外网开放，也不会改写任何状态。
* 演完后服务会一直挂着，方便你慢慢回看；按 `Ctrl+C` 结束。
* 不想被自动重载打断（比如正停在某个时刻细看），加 **`--no-serve-reload`**：演完后右下角会
  滑出一个「演算完成」提示（右上角有 `×` 可先关掉），点里面的「立即查看」再切到完整结果页。
* `--no-open` 用于不想自动弹浏览器（如远程/无头环境），手动访问打印出的地址即可。
* 它和 `--live` / `--log` / `--export` 可以叠加：同一份编年史既刷屏 / 落盘，也喂给看板。

## 七、配置速查：改什么、会怎样

| 文件 | 管什么 | 改了会不会动轨迹 |
|---|---|---|
| `config/params.json` | 所有阈值与周期；**判据表** `verdict_rules`；输出详细度 | **会**（数值类几乎都会） |
| `config/loci.json` | 十二个位：位次、容量、衰减、耦合矩阵 | **会** |
| `config/mapping.json` | 命途向量 → 可观测量的泛函矩阵 | **会** |
| `config/operators.json` | 算子装配顺序、哪些算子需要外部开关 | **会** |
| `config/seeding.json` | 播种：每位几个、采样分布 | **会** |
| `config/conclusions.json` | 结论文案、裁决短名、停因长句 | 不会（只影响渲染） |
| `config/lexicon.json` | 词表：术语 / 城邦区域 / 能力 / 纪元 / 月份 / 停因 | 不会 |
| `config/phonology.json` | 音位表与语料：名字怎么拼 | 不会（名字不参与运算） |
| `config/calendar.json` | 帧 → 光历的刻度映射 | 不会 |
| `config/invariants.json`、`policies.json` | 违例定义与调度策略 | **会** |
| `data/genesis.json` | 命题与初始变量域（含 `disorder`，直接决定 `progress`） | **会**，且影响最直接 |
| `presets/*/events.jsonl` `disturbances.jsonl` | 外生剧本（投递什么、什么时候） | **会**（`emit` 除外，它只记账） |
| `presets/*/actors.json` | 外部实体表与权限 | 不会（除非被 `revise_protocol` 用到） |
| `presets/*/anchors.jsonl` `lexicon.json` `timeline.json` `assertions.jsonl` | 名字绑定 / 词表覆盖 / 期望清单 / 判据 | 都不会 |

> **改完记得跑 `python tools/snapshot.py`** —— 它会告诉你轨迹到底有没有动，以及动了哪些读数。

## 八、自检与诊断

```bash
python tools/selfcheck.py            # 一把梭：两条红线 → 环境 → 单测 → 判据 3 → 世界 → 指纹
python tools/selfcheck.py --full     # 再加四个世界的全量验收 + 判据 4/5（帧截断复现 / 复用等价）
python tools/selfcheck.py --list     # 只列出当前会跑哪些步骤
python tools/snapshot.py             # 轨迹指纹：改了引擎先看这个
python tools/snapshot.py --structural # 只比【结构层】（跨平台用：跳过数值层与 digest）
python tools/snapshot.py --write     # 确认轨迹该变时，重写指纹
```

> **指纹是分层的**：**结构层**（裁决 / 结论 / 停因 / 帧号 / 换代 / 人数 / 席位 …，全整数与枚举，**逐位严格、跨平台可比**）、**数值层**（`entropy` / `noise`，走**容差** 1e-6）、**摘要层**（`digest`，量化 float32 向量的哈希，**只在同一参考环境上逐位可比**）。`tests/golden_fingerprints.json` 顶层的 `_reference_platform` 记着指纹是在什么环境里写的（`system` / `machine` / `python` / `numpy` 四项）；**任一项不同**，`selfcheck` 就**自动降级**为 `--structural`（CI 因此在 `ubuntu-latest` 上跑，只比结构层）。

其中两条**红线**（`grep_forbidden` 禁专有名词、`stepwise_lint` 禁解析求解 / 预读未来）
都已收进 `selfcheck` **快档**；**判据 6**（`writeback_probe`：全程零写入 `data/`）也在快档，
**判据 5**（`reuse_equivalence`：复用是否伪造世界状态）在 **`selfcheck --full`** —— 都不必手动再跑。

个别工具按用途分：

| 想知道什么 | 用哪个 |
|---|---|
| 我改的引擎有没有挪动世界？ | `tools/snapshot.py`（逐位 digest + 关键读数） |
| 换掉席的编号 / 名字，世界会变吗？ | `tools/shuffle_loci.py`（**判据 1 重标定不变性**：把 id 随机置换后重跑，读数必须逐项不变） |
| 从第 k 帧续跑，和全程跑到那里一样吗？ | `tools/checkpoint_replay.py` |
| 复用参考轨道有没有伪造世界状态？ | `tools/reuse_equivalence.py`（**已进 `selfcheck --full`**） |
| 换命名器 / 音位表，轨迹会变吗？ | `tools/naming_orthogonality.py` |
| 哪些种子能命中剧情预设？ | `tools/seed_probe.py --preset plot --seeds 0:64 --jobs 8` |
| 有没有角色信息被写回 `data/`？ | `tools/writeback_probe.py`（判据 6，**已进 `selfcheck` 快档**；应为无） |
| 死了谁、因何而死、被谁？ | `tools/roll_call.py`（登场/陨落总账 + 外生干预下的伤亡 + 承位链） |
| 每一席各自经历了什么（诞生/消亡/易主/承载）？ | `tools/excavation.py`（`--json` 出机器可读档案） |
| 桥段帧号该往哪挪，才能打在点名角色身上？ | `tools/mech_align.py` |
| 这个扰动的效果是「结构性的」还是「混沌噪声」？ | `tools/mech_control.py` |
| 改哪个旋钮会改判？ | `tools/sensitivity.py`（只认 `operators.STAGE_TUNABLE` 里真会读的键） |

## 九、扩展指南

### 9.1 加一条外生剧情事件

编辑 `presets/plot/events.jsonl`，一行一条：

```json
{"frame": 23000, "channel": "world", "capability": "emit",
 "selector": null, "label": "◆ 这里写世界内的措辞（预设层允许专有名词）",
 "payload": {"event": "anaxa_proves"}}
```

* 只用**记账**、不改动力学 → 用 `emit`（它写进账本，可由 `emitted_events` 断言核对）。
* 要真的改状态 → 换成 `suppress_slot` / `evict_holder` / `parley` / `bind_participant` / `raise_noise` / `gaze` / `interstice` 等（清单见 `engine/disturbance.py` 的 `CAPABILITIES`）。
  * `evict_holder` 是**暴力**手段：把该席在位者逐出并**处死**（`evicted` 计数 +1）。
  * `parley` 是**和平**手段：「陈说利害，指望对面自己交出手里的那一份」。它**看状态**才谈得成 —— 判据是「**该席手里空着**」且「**黑潮没压过谈判门**」（门槛由 `noise` 抬高）。谈成 ⇒ 在位者**自愿离位、不死人**；谈不成 ⇒ 什么都不发生。于是「黑潮侵蚀 ⇒ 神志不清 ⇒ 谈不拢 ⇒ 只能打」这条链是**自动成立**的，不必额外发明。
  * 另有 `plead` / `barter` 两个**只入账、不动世界**的能力 —— 「改不了世界一丝」的语义是**刻意保留**的（永劫回归的留痕判定依赖这一点）。
  * `bind_participant` 让一位**场外参与者**（带外编号 < 0，如 `-2`）接掌选中的席：`{"capability": "bind_participant", "selector": {"expr": "order:0"}, "payload": {"participant": -2}}`。他不在池中、不算涌现、此席不被活体争夺。
* 想让引擎**核对**「这条剧情有没有跑到」，在 `presets/plot/timeline.json` 里加一个节点：

```json
{"id": "N30_MY_BEAT", "feature": "emitted_events", "op": "contains",
 "value": "anaxa_proves", "by": 23000, "label": "我的剧情里程碑"}
```

### 9.2 加一个世界（预设）

预设目录至少要有 `preset.json`。最常见的做法是复制一份现有预设再改：

```
presets/我的世界/
  preset.json         {"name": "我的世界", "seed": 0, "note": "……"}
  anchors.jsonl       名字锚定：把某个编号钉在某个名字上（可选；只改渲染，不改轨迹）
  disturbances.jsonl  外生剧本
  events.jsonl        一次性剧情事件
  actors.json         外部实体与权限（可选）
  lexicon.json        词表覆盖（可选；换一套词就说成另一个神话）
  timeline.json       期望清单（可选）
  assertions.jsonl    判据（可选）
```

跑 `python run.py --list-presets` 能立刻看到它。**预设不能改 `config/`** —— 这是刻意的：预设只提供「演算之外」的东西。

### 9.3 加一个新的结论维度（**不必改代码**）

这是本项目后期工程化最值钱的一条。四步全在配置里：

1. `config/params.json` 的 `verdict_rules` 里加一行：

```json
{"id": "my_verdict", "when": "all_falsified", "ascends": true,
 "require": [{"counter": "destruction_events", "min": 240}]}
```

   * `when` 是**情形**，目前有两种：`all_falsified`（十二位全部被证伪）/ `stalled_and_exhausted`（结构冻结且变量域穷尽）。
   * `require` 是**附加条件**列表，每项恰好含一个条件键，目前有两种：
     `{"solver": "OP_..."}`（当前演算方向须等于它）、`{"counter": "某账本计数", "min": 阈值}`。
   * `ascends` 标出「未被改写时演算主体是否升格外溢」。
   * **顺序即优先级**，第一条成立者即答案。
   * 情形与条件的注册表在 `engine/verdicts.py`（`WHEN` / `REQUIRE`）—— 要加**新的**情形或条件才需要写代码；
     用**既有**情形 + 既有条件拼出来的新维度，仍然全在配置里。字段名写错（含 `solver` / `counter` 的取值）**启动即报**。

2. `config/conclusions.json` 里补一条文案，`id` / `template` / `label` / `stop` / `stop_label` 都要（报告要用它当短名）。
   * 该文件顶层的 `_framing`（可选、**不是**一个结论维度）是一句**全局说明**，报告会在裁决段开头打印它 —— 它把「裁决」定性为**测量**而非形式证明。改它只改措辞，不碰任何判据。

3. 想让它**真的可达**（不要留死代码），得有一个世界走得到它 —— 见 §9.2 新造一个预设（`presets/destruction/` 就是范例：最小的退化预设，无剧情、无名字，只拨一次演算方向）；或者在单测里造一个最小世界证明它能触发（`tests/test_verdicts.py` 就是范例）。

4. `python tools/snapshot.py` —— 若既有世界不该受影响，它会告诉你有没有被波及。

### 9.4 改完必做的三件事

```bash
python tools/grep_forbidden.py     # 红线 1
python tools/snapshot.py           # 轨迹有没有动
python tools/selfcheck.py          # 全套
```

若轨迹**该**变（改轨道配置、改外生剧本），跑 `python tools/snapshot.py --write` 重写指纹，并同步更新 `presets/*/timeline.json` 的 `_observed_seed0` 与 `assertions.jsonl`。

## 十、常见问题

**Q：报告里「沿参考轨道复用 N 帧」是什么意思，算作弊吗？**
不是。世界结构进入冻结后，后续帧的演化结果与复用前的同一帧逐位相同，于是直接沿用而不重算。`tools/reuse_equivalence.py` 专门核对这一点。

**Q：我 `--frames 3000` 跑出来一堆 FAIL，是坏了吗？**
不是。断言与时间线是按**全量预算**写的，跑不满自然核不上。要验收就跑完整预算。

**Q：`--explore` 能当验收吗？**
不能。它压缩了时间刻度与事件帧，帧号与锚定编号都会失效，报告里会写明「探路档：跳过」。它只用来几秒内确认机制还连通。

**Q：换个种子，结论会变吗？**
不会。`seed` 只影响角色涌现与命名（谁长出来、叫什么），不改变裁决结果与时刻。

**Q：为什么引擎里连「毁灭」两个字都不能写？**
因为引擎要通用：它只认 `destruction` 这个枚举。中文文案放 `config/conclusions.json`，于是换一套配置就能讲另一个故事。这条由 `tools/grep_forbidden.py` 强制执行。

**Q：看板能离线看吗？**
能。`--export` 出的是单文件、内联一切、不联网，拷到任何机器上用浏览器打开即可。

**Q：`--serve` 会把我的机器暴露到外网吗？**
不会。它只监听 `127.0.0.1`（本机回环），且是**只读**的：页面只向 `state` 取数，不接受任何写入，也不改变演算结果。

**Q：看板里的曲线为什么看不到最后一次世代更迭？**
现在能看到了。曲线右端固定是**演算真正走到的那一帧**，世代更迭的竖虚线也改用**真实事件记录**绘制（不再从采样点推断），所以最后一次换代一定落在图上。

**Q：单测要装 pytest 吗？**
不用。全部用标准库 `unittest` 写的（pytest 也能直接收集）：`python -m unittest discover -s tests`。
